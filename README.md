# Subtitle Editor

Локальный веб-редактор субтитров: FastAPI, faster-whisper и браузерный интерфейс.
Docker для запуска не нужен.

## Быстрая установка на Mac и Windows

Скачайте [ZIP репозитория](https://github.com/albert999-pixel/subtitle-editor/archive/refs/heads/main.zip)
через **Code → Download ZIP** и распакуйте в постоянную папку.
Можно также выполнить `git clone https://github.com/albert999-pixel/subtitle-editor.git`.
Установите [Python 3.11](https://www.python.org/downloads/).
На Windows при установке отметьте **Add python.exe to PATH** и установку Python Launcher.

| Действие | macOS | Windows |
| --- | --- | --- |
| Установить зависимости, один раз | `install.command` | `install.bat` |
| Запустить приложение | `start.command` | `start.bat` |

Запускайте файлы двойным щелчком. Установка требует интернета. При повторной установке
скрипт проверит зависимости, сохранив настройки и модели. Запуск открывает браузер
по адресу http://127.0.0.1:5002. Оставьте окно терминала открытым.
Для остановки нажмите **Ctrl+C** в этом окне. Закрытие вкладки браузера сервер не останавливает.

Если macOS запрещает открывать скачанный `.command` или ZIP не сохранил права,
откройте Terminal, перейдите в папку проекта и выполните `bash install.command`,
затем `bash start.command`. Не требуется отключать защиту системы.
На Windows запускайте из распакованной папки, а не внутри ZIP.

Python установлен в системе, а пакеты приложения — в `.venv` проекта.
Настройки находятся в `.env`, модели в `models/`, аудио в `temp/`,
кеш установки и скачивания в `.cache/`. Эти папки и секреты не публикуются.
Виртуальное окружение нельзя переносить между компьютерами: переносите исходники
и модели, затем снова запускайте установку. Облачный режим работает без моделей.

Поддерживаемая версия Python — **3.11**. Локально проверяется macOS ARM64;
для Windows, macOS и Linux предусмотрены проверки GitHub Actions.
Ручная проверка интерфейса на Windows всё равно нужна. На старых ОС доступность
бинарных пакетов может отличаться; текущий набор для Mac рассчитан на macOS 14+.

## Установка вручную

macOS:

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/manage.py start
```

Windows (PowerShell):

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts/manage.py start
```

Если порт занят другой программой, запустите с `--port 5003`.
Параметр `--no-browser` запускает сервер без открытия браузера.
Установка зависимостей происходит только по команде установки, а не при каждом запуске.

## Локальные модели

Модели скачиваются вручную через браузер с Hugging Face. Приложению нужен
формат **faster-whisper / CTranslate2**. Обычные модели OpenAI Whisper в формате
`.pt`, `safetensors` или GGUF не подходят.

1. Откройте вкладку **Files and versions** нужной модели:
   [Large v3 Turbo](https://huggingface.co/dropbox-dash/faster-whisper-large-v3-turbo/tree/main)
   или [Small](https://huggingface.co/Systran/faster-whisper-small/tree/main).
2. Создайте отдельную папку, например `models/large-v3-turbo/`.
3. Скачайте туда `model.bin`, `config.json`, `tokenizer.json` и файл словаря
   (`vocabulary.json` или `vocabulary.txt`, в зависимости от модели).
   Если есть `preprocessor_config.json`, скачайте его тоже.
   Для каждого файла используйте кнопку скачивания на Hugging Face.
4. Все файлы должны лежать непосредственно в папке модели, без дополнительных
   вложенных папок. Не сохраняйте веб-страницу вместо файла.
5. Обновите страницу приложения и выберите локальную модель в настройках.
   **Сначала скачайте SRT, если в редакторе есть несохранённые правки:** обновление
   страницы сбрасывает состояние редактора.

Подробная инструкция, ссылки на остальные размеры и пример структуры находятся
в [models/README.md](models/README.md). Эта инструкция включена в ZIP репозитория,
сами модели — нет. Для облачного Groq скачивать модель не требуется.

## Загружаемый файл

Для транскрибации нужен MP3, M4A, MP4, WAV, FLAC, OGG или WEBM с аудиодорожкой.
SRT и пустые файлы отклоняются при выборе или перетаскивании.
Сервер дополнительно проверяет, что файл содержит читаемое аудио, до обращения
к Groq или локальной модели. Одного переименования SRT в WAV недостаточно.

## Распознавание через Groq

В настройках выберите «В облаке · Groq», вставьте ключ из
https://console.groq.com/keys и сохраните настройки. Доступны Whisper Large v3
Turbo и Whisper Large v3. Локальная модель для этого режима не нужна.
Аудио отправляется в Groq; бесплатный тариф имеет ограничения аккаунта.
Большие файлы могут быть отклонены сервисом (автоматического разбиения пока нет).

Ключ хранится в локальном `.env`, исключённом из Git, и не возвращается браузеру.
Пустое поле ключа сохраняет существующий ключ. Для удаления предусмотрена
отдельная кнопка. Выбор режима и облачной модели сохраняется между запусками.
Оба режима сейчас настроены на русский язык.

## Экспериментальная разбивка ИИ

Вкладка «Разбивка ИИ» предлагает новые границы титров через Groq GPT OSS 120B.
Нажмите «Предложить разбивку», проверьте предпросмотр и нажмите «Применить».
Само открытие вкладки не отправляет запросов. Используется ключ из `.env`.
В Groq отправляется текст редактора, аудио для этой операции не требуется.

Один запуск делает один запрос без автоматических повторов, максимум 600 слов
и 10 000 символов. Правила находятся в `prompts/subtitle_split.md` и читаются
при каждом запросе. GPT OSS получает цельный текст и возвращает сами короткие
фразы в JSON `lines`, а не номера границ. Длина берётся из изменяемого поля
«Макс. символов» (по умолчанию 24). Вызов использует reasoning_effort=low,
temperature=0.35 и до 4096 токенов ответа. Один запуск — один запрос.

Приложение вычисляет границы по предложенным фразам и собирает предпросмотр
из исходных слов. Если модель добавила, пропустила или изменила слова,
последовательности сопоставляются с контекстом; исходный текст, регистр и
пунктуация восстанавливаются, а приблизительные границы отмечаются предупреждением.
Повторяющиеся слова сопоставляются как последовательность, а не отдельные совпадения.
Связующие слова в конце титра («в», «и», «не» и другие) переносятся вперёд
в следующий титр; такие корректировки тоже перечисляются в предупреждении.
Этот простой список правил не заменяет понимание смысла: результат надо просматривать.

Превышения длины подсвечиваются, но не мешают применить предложение.
Даже длинное одиночное слово остаётся целиком. Любой полученный ответ отображается
дословно в блоке «Исходный ответ модели», в том числе неполный JSON. Если ответ
невозможно сопоставить с текстом, весь исходный текст остаётся одним титром.
Когда Groq отклоняет JSON, но возвращает сгенерированный ответ, он тоже показывается;
если сервис вообще не вернул текст ответа, отображается понятная ошибка.
Можно применить предпросмотр, перегенерировать или отказаться.

При перегенерации модель получает прошлые фразы и просьбу улучшить слабые места.
Другой вариант возможен, но не гарантирован. Исходный ответ модели не меняется
при локальных корректировках. Это позволяет отличать поведение модели от обработки
в приложении и редактировать промпт по результатам.
Отметки сохранения регистра переносятся на новые титры, применение можно отменить.
Результат может объединить повторяющиеся пробелы в одиночные, но не меняет слова.

## Экспорт SRT

В режиме «Выделение» отметьте имена, названия и аббревиатуры, регистр которых
нужно сохранить. Кнопка «Строчные, кроме выделенных» переводит все остальные
слова во всех титрах в нижний регистр. Отмеченные слова остаются как написаны;
строчное имя автоматически не превращается в заглавное. Действие можно отменить
через Cmd+Z / Ctrl+Z. Отметки не добавляют цветовые теги в SRT.

Каждая непустая строка редактора экспортируется один раз, в порядке редактора.
Исправленные фразы сопоставляются с исходной последовательностью слов; замены
получают временной диапазон заменённого фрагмента. Если сопоставить текст нельзя,
строка всё равно сохраняется с приблизительным временем.

Минимальная длительность титра — 0,5 секунды. Пересекающиеся или слишком короткие
интервалы сдвигаются/продлеваются вперёд. При большом числе коротких титров итог
может выйти за длительность аудио. Финальную привязку к склейкам следует делать
в монтажной программе. Пустые строки не экспортируются.

Проверки экспорта:

```sh
.venv/bin/python -m unittest discover -s tests -v
```

## Структура проекта

- `app.py` — HTTP-маршруты и запуск приложения.
- `config.py` — чтение и сохранение локальных настроек.
- `transcription.py` — локальное и облачное распознавание.
- `srt.py` — сопоставление текста с аудио и экспорт SRT.
- `ai_split.py`, `prompts/subtitle_split.md` — экспериментальная смысловая разбивка.
- `web/index.html` — разметка и стили интерфейса.
- `web/editor.js`, `web/case-tools.js` — логика редактора и операции с регистром.
- `tests/` — проверки приложения.
- `.env.example` — пример настроек без ключа.

`requirements.txt` фиксирует проверенные версии всех необходимых зависимостей.
Локальные `.env`, `.venv`, файлы моделей и `temp/` не предназначены для публикации.
JavaScript-проверки выполняются командой `node tests/test_case_tools.cjs` (Node.js
нужен только для этих проверок, приложение запускается без него).

## Docker

Приложение использует тот же код в контейнере. Dockerfile устанавливает Python
и зависимости; внешний порт по умолчанию тоже 5002. Остановите обычный запуск
перед запуском Compose или измените внешний порт в `compose.yaml`.

```sh
docker compose up --build -d
# Открыть http://127.0.0.1:5002
docker compose down
```

Модели подключаются из папки `models/` только для чтения. Настройки, включая
ключ, введённый через интерфейс, сохраняются в Docker volume `subtitle-settings`.
Обычный `docker compose down` сохраняет их; `down -v` удаляет настройки.
Готовый образ не содержит ключей, моделей и пользовательского аудио.

При запуске готового образа через Docker Desktop задайте внешний порт `5002`
для внутреннего `5001`. Для сохранения настроек подключите volume к `/data`,
для локальных моделей — папку к `/models`. Ключ можно ввести в интерфейсе
или передать переменной окружения `GROQ_API_KEY`. Ключ из окружения имеет приоритет,
не записывается в `.env` и изменяется через параметры контейнера с перезапуском.
По умолчанию Compose использует ввод ключа в интерфейсе.

Дополнительные переменные путей: `SUBTITLE_CONFIG_DIR` (папка с `.env`),
`SUBTITLE_MODELS_DIR`, `SUBTITLE_TEMP_DIR`. Обычный запуск использует папку проекта.
Образ можно собрать локально командой `docker build -t subtitle-editor:local .`.
Публикация готового образа в Docker Hub выполняется отдельно.
