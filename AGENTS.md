# Контекст для ИИ-ассистента

## Назначение и приоритеты

Subtitle Editor — локальное веб-приложение для подготовки русских субтитров
к монтажу. Пользователь загружает аудио, получает транскрипцию с таймингами слов,
делит текст на смысловые титры, исправляет распознавание и экспортирует SRT.
Один титр должен занимать одну строку; желаемая длина по умолчанию — 24 символа
с пробелами и пунктуацией. Пользователь может менять лимит в интерфейсе.

Главный приоритет: каждый непустой титр должен попасть в SRT ровно один раз,
с тем же текстом и в том же порядке, что в редакторе. Точная привязка к склейкам
дорабатывается вручную в монтажной программе. Не жертвуй сохранностью титров
ради точности таймингов или ограничения длины.

## Архитектура

- `app.py`: FastAPI, настройки, список моделей, фоновая транскрибация,
  статус обработки, аудиоплеер, экспорт SRT, запрос смысловой разбивки.
- `config.py`: локальные настройки в `.env` с приоритетом переменных окружения. Только режим распознавания,
  модель Groq и API-ключ. Устаревшая настройка цвета удалена.
- `transcription.py`: локальный faster-whisper (CPU, int8) либо Groq Whisper.
  Оба режима возвращают `[{word, start, end}, ...]`, язык сейчас русский.
- `srt.py`: сопоставление исходной и отредактированной последовательностей
  через `SequenceMatcher`, приближённые тайминги замен/вставок и генерация SRT.
- `ai_split.py`: Groq `openai/gpt-oss-120b` возвращает только границы титров.
  `prompts/subtitle_split.md` читается при каждом запросе, его можно редактировать.
- `web/index.html`: разметка и стили. `web/editor.js`: состояние и действия
  редактора. `web/case-tools.js`: чистые операции с регистром и отметками слов.
- `tests/`: Python unittest и JavaScript-проверки без дополнительных тестовых библиотек.

`scripts/manage.py` и `.bat`/`.command`: установка в `.venv` и запуск.
Модели скачиваются вручную с Hugging Face; инструкция — `models/README.md`.
Скрипты скачивания удалены по просьбе пользователя.
Dockerfile и Compose используют тот же код; настройки в volume `/data`,
модели в `/models`, временные файлы в `/tmp/subtitle`.

Основные маршруты: `/api/health`, `/api/config`, `/api/local-models`, `/api/transcribe`,
`/api/status`, `/api/audio`, `/api/audio-ready`, `/api/build-srt`, `/api/ai-split`.

Состояние редактора находится в браузере: строки `{text, preservedCase: Set}`,
исходные `wordTimings`, история отмены/повтора. Автосохранения проекта нет:
обновление страницы теряет правки. Сервер хранит один общий статус транскрибации
и один текущий аудиофайл; это приложение для одного пользователя, не многопользовательский сервис.

## Правила поведения

1. Экспорт никогда не ищет каждое одинаковое слово независимо по очереди
   совпадений: такой старый алгоритм терял исправленный текст и ломал порядок времени.
   Сопоставляй последовательности с контекстом; полностью переписанные строки
   тоже обязаны экспортироваться.
2. Интервалы SRT формируются в целых миллисекундах, минимум 500 мс,
   без пересечений и обратного времени. При необходимости следующие титры
   сдвигаются вперёд, даже за конец аудио. Пустые строки не экспортируются.
3. Режим «Выделение» сохраняет регистр отмеченных слов. По кнопке остальные
   слова во всех строках становятся строчными. Отмеченные слова остаются
   как написаны, автоматически заглавными не становятся. Цветовых тегов SRT нет.
4. Разбивка ИИ запускается только кнопкой, один запуск — один запрос без
   автоматических повторов. До 600 слов и 10 000 символов. Модель получает
   текущий лимит и при перегенерации прежние границы. Она не переписывает слова:
   строки собираются локально по строго возрастающим конечным позициям (с 1).
   Все слова должны быть покрыты ровно один раз и в исходном порядке.
5. Превышение длины в экспериментальном режиме — предупреждение в предпросмотре,
   а не запрет применения. Даже длинное одиночное слово допустимо. Неполный
   ответ или неверные границы отклоняются. Предложение применяется явно;
   устаревшее после изменения текста/лимита предложение применять нельзя.
   Применение сохраняет отметки регистра и отменяется через Cmd+Z / Ctrl+Z.
6. Не возвращай API-ключ в HTTP-ответах и не выводи его в логах, командах или чате.
   Пустое поле ключа в интерфейсе сохраняет прежний ключ; удаление — отдельная кнопка.
   `.env`, `.venv`, файлы моделей и `temp/` исключены из Git;
   `models/README.md` публикуется. `.env.example` не содержит секретов.

Загрузка проверяется в браузере (расширение и ненулевой размер) и на сервере
(плюс декодирование аудиокадра через PyAV). Неподходящие файлы не отправляются
провайдеру и не удаляют предыдущую запись.

## Запуск и проверки

Проверенное окружение — Python 3.11 на macOS ARM64. Настройка окружения
и команды для Windows описаны в `README.md`. Установка и HTTP-запуск прошли
CI на Windows, macOS и Linux; ручная проверка интерфейса на Windows нужна отдельно.
Установщик и запуск через `.bat`/`.command` описаны в README. Docker необязателен.

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 5002
.venv/bin/python -m unittest discover -s tests -v
node tests/test_case_tools.cjs
.venv/bin/python -m pip check
```

Node.js нужен только для JavaScript-проверок. `python app.py` и start-скрипты
используют loopback-порт 5002; контейнер внутри использует 5001. Версии зависимостей зафиксированы; многие
пакеты в requirements являются необходимыми транзитивными зависимостями.

При изменениях проверяй пропуски/повторы титров, исправление целого слова или
фразы, вставки и удаления, повторяющиеся слова, нулевые интервалы, округление
на границах минут, регистр, отмену/повтор и валидацию ответа ИИ.
Живые облачные запросы не входят в автоматические тесты; тесты используют моки.

## Состояние и дальнейшие этапы

Код восстановлен из старого Docker-приложения и переработан для самостоятельного
запуска. Локальная модель лежит в игнорируемой папке models и не войдёт в репозиторий.
Есть рабочие локальная/облачная транскрибация, экспорт, сохранение регистра и
экспериментальная смысловая разбивка. Пользователь тестирует версию в работе.
Пользователь разрешил публичный репозиторий albert999-pixel/subtitle-editor.
Установщики Mac/Windows и Docker-упаковка добавлены. Матрица CI проверяет три ОС;
ручные проверки на Windows нужны отдельно. Docker Hub публикуется отдельным этапом.

Обновляй этот файл при существенных изменениях устройства или поведения программы.
